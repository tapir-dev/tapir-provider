# Fetched model layer discovers ids live and caches them beside the user file

The fetched layer of the Catalog (behind `models-fetch`, middle precedence: user > fetched > baseline) is populated by `ModelRegistry::refresh`, which issues a best-effort `GET /v1/models` per compiled-in Provider over the injected `HttpClient` seam, and is persisted to an on-disk JSON cache tagged `tapir.models.fetched.v1` that a later `load` reads back. Each Provider's routing (base URL, wire API, and thus its auth header) is derived from that Provider's existing Catalog entries, and the fetch merges the returned ids over the baseline by id — only ever *adding* a Model the Catalog lacks, never overriding one it has — so precedence holds regardless of layer order. The cache lives beside the user-override file (`.../models.toml` -> `.../models.fetched.json`), so a single `models_path` carries both overlay layers. We chose an add-only merge of bare ids over reconstructing full Model metadata from `/models` because the endpoints return little beyond an id, and a discovered Model only needs its Provider's routing plus a Credential to be callable; its limits and cost stay unknown (zero) until a baseline generation fills them.

## Consequences

- The fetch is best-effort per Provider: one with no resolved Credential, a wire API this crate has no adapter for (no known endpoint), or a failing request keeps its last-known ids rather than dropping them, because `refresh` starts from the persisted cache and overwrites only Providers that answer.
- The cache is derived and disposable: it is size-bounded (max bytes, max providers, max models per provider) and rejects unknown fields, and any missing, malformed, mistagged, or over-bounds cache is skipped on `load` rather than failing it — so a bad cache never breaks a load, unlike the user layer.
- A synthesized fetched Model carries zero context-window/max-tokens and text-only input, since `/models` does not report them; callers wanting full metadata rely on the baseline (ADR-0006) or the user layer.
- `refresh` surfaces an error only when the cache cannot be written; a network or parse failure is swallowed as a non-update.
